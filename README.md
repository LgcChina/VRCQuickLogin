# LGC VRC 一键登录 v1.1.5

在 VRChat SDK 原登录页附加“快捷登录”，选择已保存的账号即可填写账密。
主面板管理多个账号、密码和备注，并决定选中后是否自动提交登录。不修改 SDK 文件，不监听或收集原登录框中的输入。

## 使用

1. 通过下面的 ALCOM/VPM 方式安装，或导入整个工具目录并保留 `.meta`，打开 `LGC > VRC 一键登录`。
2. 填写账号或邮箱、密码、备注，点击 **保存 / 新增**。备注可不填；先点击 **清空输入** 可退出编辑并准备新增。
3. 编辑已有账号时点击列表记录或其 **编辑** 按钮。每条账号有独立按钮边框、底色和间距，选中后高亮；列表至少显示四条后才滚动。密码留空可保留原密码；更换账号必须填写密码。
4. 打开 VRChat SDK 的 **Authentication** 页，点击原 Account 登录框下方的 **快捷登录**，列表显示备注和账号，选中所需记录。
5. 主面板的 **选择后自动点击登录按钮** 默认开启，选中即调用 SDK 原有 Sign In；关闭后只填写，由你手动点击 SDK 的 Sign In。
6. 工具只使用所选账号保存的账密，通过 SDK 原有登录流程提交。首次登录和需要邮箱/身份验证器验证码时，继续在 SDK 面板手动完成。

快捷列表中的 **管理账号** 可直接打开主面板。列表可滚动，不读取所有账号密码；只有选中账号或执行管理操作时才读取相关密码。
快捷入口在原 Account 框外侧下方居中、与登录区域同宽，不嵌入 Sign up 所在的原边框内部；不改写 SDK 的 IMGUI 绘制。
账号弹窗与快捷按钮同宽，以按钮矩形作为锚点优先向下展开；屏幕空间不足时由 Unity 自动避让。
按钮在独立 IMGUIContainer 中绘制，由 Unity 对本地坐标做一次屏幕转换，不手动叠加窗口位置，避免停靠/浮动窗口坐标偏移。
未保存的编辑不会被切换记录直接丢弃，先保存或点击“清空输入”。清空输入只重置表单，不删除账号。保存后清空密码输入，不回显旧密码。
快捷入口不会主动退出或切换 SDK 当前已登录账号；SDK 已登录时不会重复提交新的账密。
打开项目、打开管理窗口、打开快捷列表、脚本重编译都不会自动提交登录；必须明确选中账号。

## ALCOM / VPM 安装

在 ALCOM 的包源管理中添加：

```text
https://lgcchina.github.io/LGC-VRC-Packages/index.json
```

然后在项目的包管理中安装 **LGC VRC 一键登录**（`com.lgcchina.vrc-quick-login`）。
需要 Windows、Unity 2022.3 和 VRChat SDK Base 3.9.0 或更新版本；可用于 Avatar 或 World 项目。
工具已在 VRChat SDK 3.9.0 与 3.10.6 上核对登录面板接口，兼容两者的 `SignIn` 静态/实例签名差异；较新 SDK 若改动内部接口仍可能需要适配。

原 Assets 版本目录列入 VPM 的 `legacyFolders`，包管理器可按路径或原目录 GUID 迁移移除旧副本。
迁移前建议备份项目；若仍提示重复类或程序集，检查并移除残留的 Assets 版，勿同时保留两份源码。
目录路径仅为项目相对路径，不包含本机用户名。密码和账号记录在项目外，不随安装、迁移或卸载包移动。

源码和版本发布：<https://github.com/LgcChina/VRCQuickLogin>。发布 ZIP 只包含编辑器工具、清单和说明，不包含任何用户账号数据。

## 本机保存

使用当前 Windows 用户的系统目录，不写死用户名、盘符或 Unity 项目路径：

```text
%LOCALAPPDATA%\LGC\Unity\VRCQuickLogin\accounts.json
```

此索引只包含账号、备注、记录 ID 和自动登录开关，不含密码或 Token。两套 Unity 项目修改时使用本机文件锁，避免同时写入覆盖。
同一电脑、同一 Windows 用户下的多个项目可共用列表和设置；换电脑或 Windows 用户后需要重新保存。

每个账号的密码优先独立写入 **Windows 凭据管理器 > Windows 凭据 > 普通凭据**：

```text
LGC.Unity.VRCQuickLogin/<记录 ID>
```

若系统凭据不可用，则按用户明确授权，降级为项目外的本机 **明文文件**：

```text
%LOCALAPPDATA%\LGC\Unity\VRCQuickLogin\Secrets\<记录 ID>.json
```

明文账号在列表中标记 **[明文]**，主面板显示风险提示。不要分享、上传或同步该文件夹，文件中包含完整账号和密码。
Windows 凭据也不对同一 Windows 用户下所有程序提供绝对隔离，请在可信设备与项目插件环境使用。
每次保存优先尝试系统凭据；写入并读回校验成功后删除对应明文文件。若仍存在降级文件，读取以其为准，避免使用残留旧凭据。
索引和明文文件均采用临时写入后替换；正常结束清理临时文件，异常断电可能留下 `.tmp`。不会另留密码备份。
密码不写入 Assets、预制件、场景、EditorPrefs 或日志；窗口密码字段不参与热重载序列化。
.NET 字符串不能保证立即从内存擦除，本工具不声称具备密码保险箱等级的内存防护。

## 升级

从 v1.0.0 升级时，第一次读取新列表会自动迁移原有单账号，默认备注为 **原有账号**，无需重填密码。
新密码记录与索引都保存成功后，才清除旧单账号系统凭据及旧 `credentials.json`。
旧记录暂不能读取时保持原样，并提示稍后重试，不阻止新增其他账号。
若迁移成功但旧记录清理失败，面板提示，下次读取重试清理。不要混用旧版工具，避免旧版重新写入另一份单账号记录。

从之前的 v1.2.0 测试版升级到 v1.1.5 时，账号列表和密码记录仍按普通多账号格式读取；v1.1.5 不再读取或恢复测试版写入的登录会话 Token。若之前测试版在 Windows 凭据管理器中留下 `LGC.Unity.VRCQuickLogin.Session/<记录 ID>`，请在确认不再需要后手动删除对应的普通凭据。 测试版的 `accounts.json` 若仍为 `version: 2`，首次打开工具时会自动忽略测试字段并归一化为普通 `version: 1` 格式。

## 删除与故障

每条记录旁的 **删除** 只删除该账号的密码记录和列表项，不删除其他账号，也不主动调用 SDK 服务端 Logout。
删除工具目录不会自动删除本机账密；不再使用时先逐一删除已保存账号，再移除工具。
密码部分删除失败时保留列表并报告，不冒充全部成功；账号索引损坏时停止覆盖，请保留本机文件排查。
账号列表和备注也是个人信息，分享工具只需分享 Assets 下的工具目录，不要附带 LocalAppData 数据。

## SDK 接入

- 基于 **VRChat SDK 3.9.0 至 3.10.6 / Unity 2022.3.22f1** 的当前源码适配；已在 3.9.0 与 3.10.6 上核对接口。
- 使用 SDK 面板启用事件附加自己的 UIElements 控件；已打开的面板也会补装，关闭重开或重编译后不重复添加。
- 控件只在未登录的 Authentication 页显示，不插入 Builder、Content Manager 或 Settings。
- 不修改包内脚本，不截获密码输入，不自己实现 VRChat API 登录，不读取或保存 SDK 会话 Token。
- 填写通过 SDK 原字段，自动登录调用 SDK 原 `SignIn(true)`，保留 SDK 的验证码、Cookie 和原有错误处理。
- 工具等待异步 SDK 初始化，防止重复提交；超时或失败不自动重试。仅向 SDK 正式环境提供账密。
- SDK 内部字段和 UI 布局不是稳定接口，未来更新可能需要适配；不兼容时停止提交，不修改 SDK 绕过问题。
- SDK 自己可能显示原有登录弹窗，本工具错误显示在管理面板或快捷区域内。

一个正式 C# 脚本，Editor 专用 `.asmdef` 配合 `#if UNITY_EDITOR`，不参与人物构建、不安装人物组件。
工具版本 **1.1.5**。脚本、窗口、README 和 CHANGELOG 同步记录版本，运行文件名称保持稳定。
编译与本机保存逻辑由工具端检查；快捷入口位置、实际填写/登录和验证码流程由用户实测。

## 发布维护

源码仓库根目录即包目录。先同步 `package.json`、窗口常量、脚本头注释、README 与 CHANGELOG 的版本，并修改清单中的版本下载 URL。
运行 `python scripts/package.py` 验证并生成 `dist` 下的 ZIP 和清单；打包严格使用文件白名单，不扫描本机账号目录。
提交后推送对应的 `vX.Y.Z` 标签，`Publish VPM Package` 工作流会发布 ZIP 和 `package.json` 两个附件。
发布完成后，在 `LgcChina/LGC-VRC-Packages` 的 Actions 中运行 `Build Repo Listing`，刷新 ALCOM 包源索引。
